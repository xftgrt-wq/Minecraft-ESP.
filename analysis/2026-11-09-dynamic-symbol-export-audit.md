# 2026-11-09 — аудит экспортируемых символов Bedrock 1.26.33

## Метод
Проверен динамический символический раздел целевой `libminecraftpe.so`:
- `readelf -Ws`: 89 746 записей в `.dynsym`;
- `nm -D --defined-only`: отфильтрованы имена, связанные с Minecraft, Actor, Level, Camera, Renderer, Hitbox и ECS.

## Результат
1. В динамических символах присутствуют JNI-точки входа Android-приложения, системные библиотеки, FreeType, Cohtml и Renoir.
2. Экспортируемых символов с именами `ActorMoveSystemImpl`, `StateVectorComponent`, `HitboxComponent`, `AABBShapeComponent`, `LevelRendererPlayer`, `CurrentViewProjectionMatrixUniform` или `MinecraftCameraPosition` не найдено.
3. Поиск по группам `Camera`, `Renderer`, `Actor`, `Level` не выявил экспортируемого Bedrock gameplay/render API; найденные renderer-символы относятся преимущественно к Cohtml/Renoir, то есть UI/рендер-инфраструктуре, а не подтверждённому миру Minecraft.

## Интерпретация и ограничения
- Это не означает, что нужные функции отсутствуют: они могут иметь скрытую видимость, быть доступны только через внутренние таблицы/виртуальные вызовы или не иметь информативных имён.
- Динамический экспорт не даёт готового безопасного API для обхода ECS и отрисовки.
- JNI-экспорты приложения не являются подходящими хуками для ESP.

## Текущий статус
Подтверждённых экспортируемых точек входа для получения сущностей, компонентов или матрицы камеры не обнаружено. Следующий технически обоснованный путь — анализ внутренних вызовов рендер-цикла и потребителей ECS storage, используя точные адреса/релокации целевого бинарника; случайные offsets из других версий Bedrock использовать нельзя.
