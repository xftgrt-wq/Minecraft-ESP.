# 2026-11-09 — поиск виртуальных вызовов слота +0xC0

## Метод
Просканирован исполняемый сегмент `.text` целевого ELF AArch64 на последовательности:
1. `LDR Xt, [Xn, #0xC0]`;
2. последующий `BLR Xt` в пределах следующих 12 инструкций.

## Результат
Найдено 1 724 совпадения по всему сегменту. В районе кода рядом с кандидатом камеры обнаружены, в частности:
- `0xbd6d904 → 0xbd6d918`;
- `0xbd76e18 → 0xbd76e38`;
- `0xbd77388 → 0xbd773a8`;
- `0xbd774bc → 0xbd774dc`;
- `0xbd776a4 → 0xbd776c4`.

Дизассемблирование показало, что эти совпадения принадлежат разным виртуальным вызовам и используют разные базовые регистры/объекты. Например, в `0xbd6d904` сначала загружается объект из `[x28+0x970]`, затем его vptr и слот `+0xC0`, после чего выполняется `BLR`. Это лишь один из множества общих виртуальных вызовов.

## Вывод
Поиск подтвердил, что виртуальные вызовы со смещением `+0xC0` широко встречаются в бинарнике. Однако совпадения нельзя автоматически связать с конкретным vtable `LevelRendererCamera`: виртуальная диспетчеризация не содержит прямой ссылки на адрес таблицы в callsite.

Таким образом, этот скан не дал уникального места вызова метода `0xbd6f97c`. Считать любой из перечисленных callsite вызовом метода камеры было бы необоснованно.

## Следующий шаг
Сузить анализ по конструкторам и RTTI: установить полный тип объекта, его базовые/вложенные подобъекты и возможные пути передачи указателя в render pipeline. Затем проверить кандидатов по контексту аргументов и обращениям к uniform descriptor, а не только по совпадению смещения vtable.
