# 2026-11-09 — RTTI и vtable LevelRendererCamera

## Подтверждённая RTTI-связь
В `.rodata` найдено имя класса `19LevelRendererCamera` по адресу `0x2bad903`. В релокациях:
- `0x141d2628 -> 0x2bad903`: указатель имени в объекте RTTI;
- `0x141d14f0 -> 0x141d2620`: ссылка на этот объект RTTI из таблицы виртуальных функций;
- `0x141d14f8 -> 0xbd62060`: первый указатель функции после RTTI.

Конструкторный путь по адресу `0xbd792a4` записывает `0x141d14f8` в начало объекта. Это подтверждает, что `0x141d14f8` — address point vtable класса `LevelRendererCamera`, а не случайный массив указателей.

## Кандидат на virtual render
В таблице на смещении `0x141d15b8` (слот 24 от address point) находится указатель `0xbd6f97c`.

Код по `0xbd6f97c`:
- сохраняет четыре входных аргумента: `x0 -> x20`, `x1 -> x22`, `x2 -> x19`, `x3 -> x26`;
- создаёт большой стековый кадр (суммарно около `0x9c0` байт);
- адрес находится в vtable именно `LevelRendererCamera`.

В бинарнике также есть строка сигнатуры `virtual void LevelRendererCamera::render(BaseActorRenderContext &, const ViewRenderObject &, IClientInstance &)` по адресу `0x254eccf`. Совпадение класса, виртуального слота и четырёхаргументного ABI делает `0xbd6f97c` сильным кандидатом на реализацию `LevelRendererCamera::render`.

## Ограничение вывода
Прямая ссылка из кода на строку сигнатуры не найдена, поэтому соответствие слота 24 методу `render` пока не считается окончательно доказанным. Адрес нельзя использовать как готовый хук без проверки пролога/эпилога, call-site и поведения на устройстве.
